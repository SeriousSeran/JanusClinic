Learning and handoff guide · Updated 6 November 2026

The current website is a customer-journey demonstration, built with React, TypeScript, Vite and Glisse. Real accounts, clinic messages, payments and appointment confirmation are still future integrations.

This guide explains what is implemented, how to make changes safely, and what is required before the Lovable application becomes patient-facing.

1. What you have now

The main page leads to Wellness, Salon and Cosmetic Care. The customer panel appears before these choices. People browse freely and identify themselves only when booking.

  • Wellness has 13 individual treatments, five signature packages, three memberships, contour programmes and a standalone free assessment.
  • Salon has 123 active services from the supplied photograph.
  • Cosmetic Care links to the original treatment guides.
  • The booking demonstration carries a selected service through identification, appointment preferences, review and a DEMO result.
  • The original 43-page capture remains unchanged in public/. The portfolio retains its historical cover images.

What “demo” means

No real account is created. No OTP or clinic message is sent. A DEMO reference is not an appointment. Fictional details remain only in browser memory and reset on refresh.

2. Start and edit

Open the same SeriousSeran/JanusClinic repository in Codex. Read AGENTS.md first. Node24 and Python3 are required.

npm ci --ignore-scripts
npm start

The local preview is http://127.0.0.1:3000. After changing source, run npm run site:build and refresh, or restart npm start.

ChangeFile
Main page, navigation, Salon, Cosmeticfrontend/App.tsx

Never edit dist/, .build/, site/generated/ or minified original bundles. They are generated output or captured reference material.

3. Prices and offerings

Wellness prices and inclusions live in frontend/data/wellness.json. Salon prices remain in content/salon/catalog.draft.json. The booking picker uses these sources too.

  • Keep stable IDs when renaming a service. Buttons carry the ID, not a copied price.
  • Salon Foot Massage: LKR5,000, 60 minutes, Salon therapist.
  • Wellness Foot Massage: LKR4,000, duration pending, Wellness therapist.
  • Contour Discovery and Contour Starter are one offering. Its area sessions are chosen after assessment; the hidden common pricing unit is not separately bookable.
  • Regular package values and savings are calculated from inclusions.
  • Cosmetic treatment pricing remains on consultation. Only explicitly complimentary consultations and assessments are free.

All supplied prices are owner-approved. Six Salon names and missing Wellness durations/clinical details remain marked for confirmation. Approval of prices does not approve cancellation, refund or carry-forward policies.

4. Design and photographs

The current palette is ivory #F5F0E8, sage #B8B5A2, deep teal #213B45, champagne #B59A70 and stone #D8CFC2. The Janus logo and Cormorant Garamond / DM Sans remain.

Glisse0.5.0 supplies the actual glass material. Its effects differ across browser engines. The adaptive Glass wrapper uses opaque panels for reduced-transparency or forced-colors preferences; prices and inputs remain readable.

The Sri Lankan model portraits are AI illustrations, not patients or results. Clinic photos retain their genuine context. Do not describe an existing Salon photograph as a massage room or manufacture an equipment image as proof of an actual facility.

Before accepting a visual change

Inspect desktop and mobile, the account/booking path, keyboard focus, prices and image crops. Keep historical reference covers unchanged; record current intentional changes in the identity guide.

5. Check and publish

npm run typecheck
npm run check
npm test
npm run test:browser
npm run preview:build
npm run test:preview

Capture checking verifies the original files. Unit checks cover offering arithmetic, validation and server/export behavior. Browser checks follow real links and demo steps.

GitHub Pages uses the repository prefix /JanusClinic/. The export creates a physical entry for each React route so direct links and refreshes work. Bundled scripts are retained for the new app; the original site’s runtime and delivery integrations are removed.

Push tested changes to main. The existing GitHub Actions workflow builds and deploys automatically. Verify the public URL and the specific changed feature before calling it published.

The preview URL is https://seriousseran.github.io/JanusClinic/. Noindex discourages indexing; it does not restrict who can visit.

6. Move toward Lovable

The maintained React source and structured catalogs can become the starting point for the Lovable application. Review Lovable’s current import/GitHub workflow when migrating; this guide does not claim a Lovable project has already been created.

First live release

  • Securely verify phone ownership before revealing a profile.
  • Store customer details privately with server validation and staff access controls.
  • Deliver booking requests with duplicate protection and clinic notifications.
  • Keep requested date/time distinct from confirmed appointments.
  • Confirm official contact details, clinic schedules, treatment suitability/guardian policies and consent text.
  • Approve package validity and cancellation/refund rules before accepting payment.

Staff management follows this foundation. Recurring billing, treatment credits, reminders and gift vouchers are later features. Do not activate these simply by changing demo text.

7. Common problems

“Environment offline” / 409 when opening an attachment

This is a chat-workspace attachment error, not a Janus application error. Temporary /tmp/codex-remote-attachments paths can expire. The catalog photograph is preserved in reference/catalogs/salon-catalog.jpg and has a stable website link on the Salon page.

Missing images after deployment

Use the shared asset and Link helpers; do not paste root-only paths into a repository-prefixed deployment. Build and test the static preview.

Glass is simpler in another browser

Glisse uses browser-dependent rendering. A readable frosted or opaque fallback is intentional; broken controls, invisible text and layout overflow are not.

Continue in another chat

Use the same repository and open HANDOFF.md. The ZIP includes source, approved decisions and feature documentation; it excludes credentials, installed dependencies, browser caches and real customer data. Install dependencies and run the checks before continuing.
